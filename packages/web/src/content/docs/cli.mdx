The VoltCode CLI by default starts the [TUI](/docs/tui) when run without any arguments.

```bash
volt
```

But it also accepts commands as documented on this page. This allows you to interact with VoltCode programmatically.

```bash
volt run "Explain how closures work in JavaScript"
```

---

### tui

Start the VoltCode terminal user interface.

```bash
volt [project]
```

#### Flags

| Flag         | Short | Description                                |
| ------------ | ----- | ------------------------------------------ |
| `--continue` | `-c`  | Continue the last session                  |
| `--session`  | `-s`  | Session ID to continue                     |
| `--prompt`   |       | Prompt to use                              |
| `--model`    | `-m`  | Model to use in the form of provider/model |
| `--agent`    |       | Agent to use                               |
| `--port`     |       | Port to listen on                          |
| `--hostname` |       | Hostname to listen on                      |

## Commands

The VoltCode CLI also has the following commands.

---

### agent

Manage agents for VoltCode.

```bash
volt agent [command]
```

---

### attach

Attach a terminal to an already running VoltCode backend server started via `serve` or `web` commands.

```bash
volt attach [url]
```

This allows using the TUI with a remote VoltCode backend. For example:

```bash
# Start the backend server for web/mobile access
volt web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
volt attach http://10.20.30.40:4096
```

#### Flags

| Flag        | Short | Description                       |
| ----------- | ----- | --------------------------------- |
| `--dir`     |       | Working directory to start TUI in |
| `--session` | `-s`  | Session ID to continue            |

---

#### create

Create a new agent with custom configuration.

```bash
volt agent create
```

This command will guide you through creating a new agent with a custom system prompt and tool configuration.

---

#### list

List all available agents.

```bash
volt agent list
```

---

### auth

Command to manage credentials and login for providers.

```bash
volt auth [command]
```

---

#### login

VoltCode is powered by the provider list at [Models.dev](https://models.dev), so you can use `volt auth login` to configure API keys for any provider you'd like to use. This is stored in `~/.local/share/voltcode/auth.json`.

```bash
volt auth login
```

When VoltCode starts up it loads the providers from the credentials file. And if there are any keys defined in your environments or a `.env` file in your project.

---

#### list

Lists all the authenticated providers as stored in the credentials file.

```bash
volt auth list
```

Or the short version.

```bash
volt auth ls
```

---

#### logout

Logs you out of a provider by clearing it from the credentials file.

```bash
volt auth logout
```

---

### github

Manage the GitHub agent for repository automation.

```bash
volt github [command]
```

---

#### install

Install the GitHub agent in your repository.

```bash
volt github install
```

This sets up the necessary GitHub Actions workflow and guides you through the configuration process. [Learn more](/docs/github).

---

#### run

Run the GitHub agent. This is typically used in GitHub Actions.

```bash
volt github run
```

##### Flags

| Flag      | Description                            |
| --------- | -------------------------------------- |
| `--event` | GitHub mock event to run the agent for |
| `--token` | GitHub personal access token           |

### mcp

Manage Model Context Protocol servers.

```bash
volt mcp [command]
```

---

#### add

Add an MCP server to your configuration.

```bash
volt mcp add
```

This command will guide you through adding either a local or remote MCP server.

---

#### list

List all configured MCP servers and their connection status.

```bash
volt mcp list
```

Or use the short version.

```bash
volt mcp ls
```

---

#### auth

Authenticate with an OAuth-enabled MCP server.

```bash
volt mcp auth [name]
```

If you don't provide a server name, you'll be prompted to select from available OAuth-capable servers.

You can also list OAuth-capable servers and their authentication status.

```bash
volt mcp auth list
```

Or use the short version.

```bash
volt mcp auth ls
```

---

#### logout

Remove OAuth credentials for an MCP server.

```bash
volt mcp logout [name]
```

---

#### debug

Debug OAuth connection issues for an MCP server.

```bash
volt mcp debug <name>
```

### models

List all available models from configured providers.

```bash
volt models [provider]
```

This command displays all models available across your configured providers in the format `provider/model`.

This is useful for figuring out the exact model name to use in [your config](/docs/config/).

You can optionally pass a provider ID to filter models by that provider.

```bash
volt models anthropic
```

#### Flags

| Flag        | Description                                                  |
| ----------- | ------------------------------------------------------------ |
| `--refresh` | Refresh the models cache from models.dev                     |
| `--verbose` | Use more verbose model output (includes metadata like costs) |

Use the `--refresh` flag to update the cached model list. This is useful when new models have been added to a provider and you want to see them in VoltCode.

```bash
volt models --refresh
```

### run

Run volt in non-interactive mode by passing a prompt directly.

```bash
volt run [message..]
```

This is useful for scripting, automation, or when you want a quick answer without launching the full TUI. For example.

```bash "volt run"
volt run Explain the use of context in Go
```

You can also attach to a running `volt serve` instance to avoid MCP server cold boot times on every run:

```bash
# Start a headless server in one terminal
volt serve

# In another terminal, run commands that attach to it
volt run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag         | Short | Description                                                        |
| ------------ | ----- | ------------------------------------------------------------------ |
| `--command`  |       | The command to run, use message for args                           |
| `--continue` | `-c`  | Continue the last session                                          |
| `--session`  | `-s`  | Session ID to continue                                             |
| `--share`    |       | Share the session                                                  |
| `--model`    | `-m`  | Model to use in the form of provider/model                         |
| `--agent`    |       | Agent to use                                                       |
| `--file`     | `-f`  | File(s) to attach to message                                       |
| `--format`   |       | Format: default (formatted) or json (raw JSON events)              |
| `--title`    |       | Title for the session (uses truncated prompt if no value provided) |
| `--attach`   |       | Attach to a running voltcode server (e.g., http://localhost:4096)  |
| `--port`     |       | Port for the local server (defaults to random port)                |

### serve

Start a headless VoltCode server for API access. Check out the [server docs](/docs/server) for the full HTTP interface.

```bash
volt serve
```

This starts an HTTP server that provides API access to voltcode functionality without the TUI interface. Set `VOLTCODE_SERVER_PASSWORD` to enable HTTP basic auth (username defaults to `voltcode`).

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

Manage VoltCode sessions.

```bash
volt session [command]
```

---

#### list

List all VoltCode sessions.

```bash
volt session list
```

##### Flags

| Flag          | Short | Description                          |
| ------------- | ----- | ------------------------------------ |
| `--max-count` | `-n`  | Limit to N most recent sessions      |
| `--format`    |       | Output format: table or json (table) |

---

### stats

Show token usage and cost statistics for your VoltCode sessions.

```bash
volt stats
```

#### Flags

| Flag        | Description                                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `--days`    | Show stats for the last N days (all time)                                   |
| `--tools`   | Number of tools to show (all)                                               |
| `--models`  | Show model usage breakdown (hidden by default). Pass a number to show top N |
| `--project` | Filter by project (all projects, empty string: current project)             |

---

### export

Export session data as JSON.

```bash
volt export [sessionID]
```

If you don't provide a session ID, you'll be prompted to select from available sessions.

---

### import

Import session data from a JSON file or VoltCode share URL.

```bash
volt import <file>
```

You can import from a local file or an VoltCode share URL.

```bash
volt import session.json
volt import https://opncd.ai/s/abc123
```

---

### web

Start a headless VoltCode server with a web interface.

```bash
volt web
```

This starts an HTTP server and opens a web browser to access VoltCode through a web interface. Set `VOLTCODE_SERVER_PASSWORD` to enable HTTP basic auth (username defaults to `voltcode`).

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

---

### acp

Start an ACP (Agent Client Protocol) server.

```bash
volt acp
```

This command starts an ACP server that communicates via stdin/stdout using nd-JSON.

#### Flags

| Flag         | Description           |
| ------------ | --------------------- |
| `--cwd`      | Working directory     |
| `--port`     | Port to listen on     |
| `--hostname` | Hostname to listen on |

---

### uninstall

Uninstall VoltCode and remove all related files.

```bash
volt uninstall
```

#### Flags

| Flag            | Short | Description                                 |
| --------------- | ----- | ------------------------------------------- |
| `--keep-config` | `-c`  | Keep configuration files                    |
| `--keep-data`   | `-d`  | Keep session data and snapshots             |
| `--dry-run`     |       | Show what would be removed without removing |
| `--force`       | `-f`  | Skip confirmation prompts                   |

---

### upgrade

Updates VoltCode to the latest version or a specific version.

```bash
volt upgrade [target]
```

To upgrade to the latest version.

```bash
volt upgrade
```

To upgrade to a specific version.

```bash
volt upgrade v0.1.48
```

#### Flags

| Flag       | Short | Description                                                       |
| ---------- | ----- | ----------------------------------------------------------------- |
| `--method` | `-m`  | The installation method that was used; curl, npm, pnpm, bun, brew |

## Environment variables

VoltCode can be configured using environment variables.

| Variable                              | Type    | Description                                       |
| ------------------------------------- | ------- | ------------------------------------------------- |
| `VOLTCODE_AUTO_SHARE`                 | boolean | Automatically share sessions                      |
| `VOLTCODE_GIT_BASH_PATH`              | string  | Path to Git Bash executable on Windows            |
| `VOLTCODE_CONFIG`                     | string  | Path to config file                               |
| `VOLTCODE_CONFIG_DIR`                 | string  | Path to config directory                          |
| `VOLTCODE_CONFIG_CONTENT`             | string  | Inline json config content                        |
| `VOLTCODE_DISABLE_AUTOUPDATE`         | boolean | Disable automatic update checks                   |
| `VOLTCODE_DISABLE_PRUNE`              | boolean | Disable pruning of old data                       |
| `VOLTCODE_DISABLE_TERMINAL_TITLE`     | boolean | Disable automatic terminal title updates          |
| `VOLTCODE_PERMISSION`                 | string  | Inlined json permissions config                   |
| `VOLTCODE_DISABLE_DEFAULT_PLUGINS`    | boolean | Disable default plugins                           |
| `VOLTCODE_DISABLE_LSP_DOWNLOAD`       | boolean | Disable automatic LSP server downloads            |
| `VOLTCODE_ENABLE_EXPERIMENTAL_MODELS` | boolean | Enable experimental models                        |
| `VOLTCODE_DISABLE_AUTOCOMPACT`        | boolean | Disable automatic context compaction              |
| `VOLTCODE_DISABLE_CLAUDE_CODE`        | boolean | Disable reading from `.claude` (prompt + skills)  |
| `VOLTCODE_DISABLE_CLAUDE_CODE_PROMPT` | boolean | Disable reading `~/.claude/CLAUDE.md`             |
| `VOLTCODE_DISABLE_CLAUDE_CODE_SKILLS` | boolean | Disable loading `.claude/skills`                  |
| `VOLTCODE_CLIENT`                     | string  | Client identifier (defaults to `cli`)             |
| `VOLTCODE_ENABLE_EXA`                 | boolean | Enable Exa web search tools                       |
| `VOLTCODE_SERVER_PASSWORD`            | string  | Enable basic auth for `serve`/`web`               |
| `VOLTCODE_SERVER_USERNAME`            | string  | Override basic auth username (default `voltcode`) |

---

### Experimental

These environment variables enable experimental features that may change or be removed.

| Variable                                        | Type    | Description                             |
| ----------------------------------------------- | ------- | --------------------------------------- |
| `VOLTCODE_EXPERIMENTAL`                         | boolean | Enable all experimental features        |
| `VOLTCODE_EXPERIMENTAL_ICON_DISCOVERY`          | boolean | Enable icon discovery                   |
| `VOLTCODE_EXPERIMENTAL_DISABLE_COPY_ON_SELECT`  | boolean | Disable copy on select in TUI           |
| `VOLTCODE_EXPERIMENTAL_BASH_MAX_OUTPUT_LENGTH`  | number  | Max output length for bash commands     |
| `VOLTCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS` | number  | Default timeout for bash commands in ms |
| `VOLTCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX`        | number  | Max output tokens for LLM responses     |
| `VOLTCODE_EXPERIMENTAL_FILEWATCHER`             | boolean | Enable file watcher for entire dir      |
| `VOLTCODE_EXPERIMENTAL_OXFMT`                   | boolean | Enable oxfmt formatter                  |
| `VOLTCODE_EXPERIMENTAL_LSP_TOOL`                | boolean | Enable experimental LSP tool            |
